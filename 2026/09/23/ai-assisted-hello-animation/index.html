尝试借助DeepSeek，在自己的网页上复刻苹果的Hello动画？

发表于2026-09-23|更新于2026-09-23
|浏览量:

hello. 手写动画设计初衷

对于一开始的个人博客首页，我使用的是hexo-butterfly模板默认的标题，仅仅一行静态的文字。UI设计是一个网站不可或缺的特点，所以我一直想让首页变得不那么平平无奇，同时也想保持着简约精练的个人风格。因此当看到自己手中的iPhone更新完 IOS 27，重启后弹出的经典你好动画，我瞬间有了思路，尝试在首页复刻这样一个动画效果，把 Apple Design 融入个人网页设计之中（大笑）。

开始的工作就是去寻找网上现有的一些实现方案，有通过AE制作动画效果，但如果要嵌入网页中，这种显得有些累赘（至少对于现在小白的我来说），当然还有通过3D设计工具制作的动图，如Apple Hello 字体动效这篇文章里作者使用Spline先绘制网络，在调整线条生成动图。此外github上也有相应的项目，AppleCurveAnimation里面作者或许没有给出一个完整的良好解决方案，但是一系列的探索也让我学习了很多。这个作者在B站上也发布了相关视频【Jrenc】我做了一个苹果线条动画生成器🥰….，同样是在B站，我还学习了代码svg复现苹果开机hello描边动画，这两者的思路是差不多的，只是绘制svg的软件不同。

总的来说得到的思路是首先生静态的svg矢量图，里面包含笔画的轨迹；然后借助CSS实现动画效果。不过上面我学习的几个方法中，svg的绘制都是手动的，看起来没那么自动，并且实践下来最终流畅度感觉会受做设计者水平（bushi）。因为本身没啥基础和经验，所以我想的是让AI来帮我一下，最终的思路就是我自己先生成静态的hello.字样的svg，然后让 Codex+DeepSeek 的agent流程帮我生成网页的动画。

文件与效果

文件 作用
位图.svg Borel 字体的 live <text> + 一条手绘参考轨迹（stroke:none，默认不可见）
位图-pen.html 自包含动画：内联了提取出的笔迹（1 条连续路径 = 整词，另 1 条 = 句点），自动循环，每遍之间停 1 秒

最终效果：整词一笔写成、中途不提笔，最后落笔点句点；循环播放，每两遍之间停顿 1 秒。

步骤

一、绘制SVG

在网上找到一个叫Borel的字体，这个字体的特色是小写字体很圆润，并且最重要的一点是一个词之间的字母是连笔的，这对于笔画生成也是有益的。另外在后面的是实现中，为了帮助DS更好的明白笔画顺序哦，我手动在字体中绘制了一条轨迹线，基本沿着笔画的中心线。这部分通过Inkscape软件实现，以下是在浏览器中打开的效果和对应的代码。这样的准备工作相比手动去绘制整个svg要轻松不少，但是交给ai的部分就变得更重了（笑）。

hello

二、动画生成

总的来说，DeepSeek的思路是：字形轮廓（填充形状）变成”一笔一笔写出来”的动画。核心是反向求出笔尖走过的单线轨迹，再用 stroke-dasharray 把它画出来。

核心难点 —— 轨迹生成

源 SVG 里的文字是填充形状（字体轮廓或描边轮廓），而描线动画需要的是单线路径。两者之间差一次”形状 → 中轴”的反向求解：想象把字形的墨水不断向中间收窄，剩下的那条线就是笔尖走过的路。

1. 位图化

用 headless Edge 截图（--headless=new --screenshot），把 viewBox 收紧到字形范围、渲染到约 2200px 宽，得到干净的黑白 mask。

坑：填充规则。 多个 <path> 各自填充时，e 和 o 的内孔会被填实 —— “o” 变成实心圆盘，中轴退化成一个点，根本没有轨迹可提。把全部子路径合并成一条 path、用 nonzero 规则填充才能恢复内孔；用 evenodd 会在笔画交叠处撕出假的白色裂缝。当时把两种规则各渲染一次做像素比对才确认。

2. 骨架化（形状 → 中轴）

  • skimage.morphology.skeletonize 得到 1px 宽的中轴
  • scipy.ndimage.distance_transform_edt 量每个骨架点的局部半宽，笔画线宽 = 2 × 中位数
  • 孤立圆点（句点）单独处理：取所在墨块最大内切圆的圆心作为落点、2×半径作为直径

3. 骨架 → 一笔一笔

  • 8 邻域建图，度数 ≠ 2 的像素是交叉点/端点
  • 游走必须在交叉点停住（否则一段会穿过交叉点，后面无法缝合）
  • 孤立像素要保留：句点的骨架可能只剩 1 个像素，会被循环直接跳过；另外零长度路径 M x y 在 Chrome 里不渲染圆头圆点，必须输出成一段极短线段
  • 短段不要删，要并入相邻笔画：阈值一开始取 0.9×线宽，把真实存在的短笔画（入笔小勾、竖腿下段）当噪声删掉了，覆盖率掉到 91%；改成”并入宿主笔画”后升到 96.6%
  • 端点按 3px 网格归并以容忍交叉点附近的错位，但判断时必须排除自己 —— 极短段的两个端点会落进同一格，否则会被误判成”挂在交叉点上”而删除
  • 缝合：在交叉点按”最接近直线”的方向把两段配对

4. 交叉点切分（关键一步）

一条基线会横跨 e→l→l，与中间的环合并成一条长笔画。这种情况下无论怎么排序，笔尖画完基线都得倒回去画中间的环，动画出现明显来回跳。

做法：若别的笔画端点到宿主笔画的最近距离 < 0.6×线宽，就在该处把宿主切开。切开后顺序才能是”基线 → 环 → 基线 → 环“，全程连续。

5. 顺序与方向（用手绘轨迹做参照）

我在在同坐标系里画了一条 stroke:none 的连续折线，手绘路径只有 m / v / l / c 四种命令，锚点之间是几十像素的直线段和少量贝塞尔段。

默认看不见，但对应坐标轨迹可以用来给DS当做”笔顺标准答案”，DS的操作是借助cKD-Tree来：

  1. 解析路径
  2. 密采样成有序点列
  3. 对每一笔的每个采样点找它在轨迹上的最近点，得到参数 t
  4. 用笔画头尾两端 t 的中位数决定它在序列中的位置和方向

具体来说，在 433 个手绘点上建 KD树，把每一笔按自身弧长重采样成 80–120 个等距点，对每个点查最近的手绘点，拿到它的下标，除以 (N−1) 得到t，每一笔都得到一条 t 序列，对应”这一笔上的每一点，是在手绘轨迹的哪个时刻被走过的。有了每笔的 t 序列，取笔画头 30% 点的 t 中位数记作 head，尾 30% 点的 t 中位数记作 tail：

最终顺序就是：用整笔t的中位数作为它在序列里的”位置”，把所有笔按它排序

验证手段：时间着色图，把手绘轨迹和字形中心线分别按时间着色（蓝 = 起笔 → 青 → 绿 → 黄 → 红 = 收笔），两边色序一致才算映射正确。DS最终也验证了顺序是有效的。

6. 首尾相接

  • 量每处接缝”落在墨迹内”的比例，全部都是 100%
  • 因此可以把 12 笔合成一条连续路径，连接段不会画出悬空飞线
  • 不过合并后不能再平滑。连接段是两端相距 200+px 的直线，1-2-1 平滑会把拐角点拉向相邻两点的平均，竖腿底部直接被拉没（覆盖率 96% → 90%）。所以合并后保持原始折线，拐角都在墨内、看不见
  • 由于一条 SVG 路径只能有一个线宽，统一用长度加权平均 ≈ 80.6（原本每笔 78.8–84），覆盖率 94.2%，在 640px 显示尺寸下差约 1px

7. HTML 动画

  • 首先需要搞清楚静态轨迹的svg代码

一条轨迹的最小表达：<path d="...">，轨迹在 SVG 里就是一条路径。d 里只有两种命令：

命令 含义
M x y 落笔：把笔尖移到 (x, y)，不画线
C c1x c1y c2x c2y x y 三次贝塞尔曲线：两个控制点 + 终点，画出一小段平滑曲线

很多个 C 首尾相接，就拼成一条连续笔迹。 所谓”笔顺”，物理上就是 d 里命令的排列顺序，不是动画参数。

目前这条路径有 242 个点，是骨架提取后经简化、平滑再转成贝塞尔的。

  • “笔迹”的五个属性
属性 使用的值 默认
fill none 默认是黑色填充，字形会整块立刻出现，完全不像在写
stroke #333333 没有描边色，什么都看不见
stroke-width 80.6 默认 1，细到看不见（一条路径只能有一个线宽）
stroke-linecap round 默认 butt，笔画两端是方头；而且”点”（零长度线段）根本画不出来
stroke-linejoin round 默认 miter，折角处会冒出尖刺
  • 坐标系与缩放
  1. viewBox 定义用户坐标系，width/height 决定显示尺寸，缩放由浏览器负责
  2. 把 viewBox 直接设成提取时的位图像素网格（viewBox="0 0 2200 879"），这样提取出的坐标拿来就用，不需要反算任何变换矩阵
  3. 页面里只写 width: 100%，字号大小随容器走
  • 分笔的两种组织方式

方式 B 的缺点：stroke-dasharray 是沿整条路径连续排布的，会跨越子路径之间的空档 —— 也就是说空白段会出现在两笔之间，导致”前一笔没画完就开始画下一笔”。所以最终选择了第三种做法：把本来就相连的笔画真正接起来，合并成一条 path（整词），句点单独一条：

这样，动画只需一条 dash 动画就能从头写到尾，中途完全不提笔；当然这样是有代价的：一条 path 只能有一个线宽，所以统一取长度加权平均，无法反应笔画轻重（虽然原本的Borel字体本身粗细比较均匀，所以肉眼看影响不大）。

另外由于零长度路径不画点。句点的轨迹收敛成一个点，写成 M 2123 802 在 Chrome 里什么都不渲染。必须写成极短线段：

使用svg实现描线动画的精髓就是没有改变形状，只改了一个数值，相当于”实线 + 空白交替”的虚线图案沿路径平移。DS画了如下图来解释：

  1. stroke-dasharray: L —— 把这条线变成”实线 L + 空白 L”交替。因为路径只有 L 长，所以看起来仍是整条实线
  2. stroke-dashoffset: L —— 把虚线图案沿路径方向平移 L，正好把那段实线推出路径之外，落在路径上的是空白 → 整条线消失

总结

这样的一个半vibe coding的动画设计让我初窥前端web开发的一些有趣的东西，同时也惊叹于DS能在我较少的调整下实现我最初期望的效果。不过回过头来看，可能我在其中绕了一些弯路，但是对于“从标准字体出发，并按照期望笔顺来生成动画的方式”，我也暂时没有想到其他可行的一些解决方案，现在我这个也有一些缺陷，比如需要人工去标记笔顺，同时最终的动画在交叉点附近不够流畅丝滑等等。

More?

在AppleCurveAnimation的README中，作者写到：

而且在英文字体里，我发现了一种字体名为Borel的字体，它可以完美的实现出连笔字的效果。我想是否可以采用一种计算方式，实现输入文字便能转换出文字线条svg？搜索发现，这个领域叫做文字图像骨架提取。

这下回头看上面 DS 在骨架化时候采取的就是**「细化法」，也就是Zhang-Suen算法，在我这个例子中可以保证1px 宽 + 像素连通 + 拓扑等价**，后面对图做遍历也最省事。

对应骨架化 / 中轴
定义：中轴变换（Medial Axis Transform）——对形状内的每一点，量它到形状边界的最近距离；如果存在两个以上等距的最近边界点，这个点就属于中轴。骨架（skeleton）通常指中轴的 1 像素宽连通版本，方便逐点处理。
三大算法家族：

  • 细化法（thinning）：迭代地剥掉满足条件的边界像素，同时保证拓扑不变（不新增断口、不填掉孔洞）。Zhang-Suen 是经典代表，两遍扫描——第一遍删除”北/东/南/西”方向的边界点，第二遍删除对角方向的，直到没有像素可删。skimage.morphology.skeletonize 走的就是这条路。
  • 距离变换脊线法：先算每个内点到边界的距离场，中轴就是距离场的”脊”。skimage.morphology.medial_axis 属于这一类。
  • 形态学骨架：用递增半径的结构元做开运算，取各次残差的并集。

对于噪声较多的图像，使用Zhang-Suen算法通常需在细化前进行平滑、二值化、降噪处理，而我准备的svg图中是由标准字体生成的，本身噪声低，所以使用Zhang-Suen算法也就顺理成章了。当然对于Zhang-Suen算法的研究，由于篇幅可以再另起一篇文字探讨一下。
